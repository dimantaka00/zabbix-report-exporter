# Pemeriksaan bug — 9 Oktober 2026

Pemeriksaan mencakup kode backend/frontend, regresi PDF dan konversi bandwidth, scheduler, Docker, API kedua Zabbix, serta alur backup. Perbaikan di bawah berada di working tree lokal; container produksi masih memakai image sebelumnya.

## Temuan yang diperbaiki

| Temuan | Dampak sebelumnya | Perbaikan |
| --- | --- | --- |
| Pemeriksaan status mengambil seluruh inventaris Zabbix | Setiap browser mengunduh ulang ribuan host beserta interface setiap 30 detik hanya untuk mengetahui koneksi | Probe `host.get` terautentikasi dengan `output: [hostid]` dan `limit: 1`; pengambilan host pada picker tetap lengkap |
| Pemeriksaan layanan berjalan berurutan tanpa batas keseluruhan per layanan | Server Zabbix lambat dapat menahan status dashboard cukup lama hingga refresh berikutnya dimulai | PostgreSQL, Redis, dan kedua Zabbix diperiksa bersamaan, dengan timeout pemeriksaan 10 detik |
| Refresh dashboard dapat bertumpuk | Klik Refresh atau timer ketika respons lama belum selesai menambah permintaan; respons lama dapat menimpa status yang lebih baru | Satu refresh aktif per halaman; permintaan dibatalkan saat halaman ditinggalkan dan respons yang dibatalkan diabaikan |
| Backup gagal saat file tracked dihapus | `git ls-files --cached` masih menyebut file yang sudah tidak ada; pembuatan ZIP berhenti | ZIP source hanya memuat file yang masih ada; bundle Git tetap menyimpan riwayat asli |

Metadata favicon juga diarahkan ke logo Kemensos yang sudah tersedia. Sebelumnya log mencatat permintaan `/favicon.ico` yang menghasilkan 404.

Parameter probe mengikuti [dokumentasi resmi Zabbix host.get](https://www.zabbix.com/documentation/6.0/en/manual/api/reference/host/get). Probe memeriksa akses API menggunakan token; respons kosong tetap valid jika user tidak memiliki host yang terlihat.

## Hasil validasi

- Backend: **90 pengujian lulus**, termasuk PostgreSQL dan Redis sementara, timeout/cancellation, probe minimal, serta pemeriksaan kedua Zabbix secara bersamaan. Suite awal sebelum perubahan juga lulus 84 pengujian.
- Frontend: `npm run build` lulus, termasuk TypeScript.
- Browser: **42 pengujian lulus** pada desktop dan mobile, menggunakan API mock. Mencakup refresh tertahan, tema, host disabled, grafik harian/bulanan, bandwidth, downtime, PDF, jadwal, dan pagination.
- Backup source: `scripts/test-backup-source.ps1` lulus menggunakan repository sementara. File tracked yang dihapus tidak menggagalkan ZIP, isi file yang diubah dan file untracked dipertahankan, `.env` tidak masuk ZIP source, dan bundle Git terverifikasi.
- Produksi: `/health/ready`, `/dashboard/status`, dan `/history` merespons HTTP 200. Backend, worker, frontend, PostgreSQL, dan Redis sehat; nginx berjalan.
- API host primary: 3.070 host, terdiri dari 1.713 enabled dan 1.357 disabled. Secondary: 3.525 host, terdiri dari 1.127 enabled dan 2.398 disabled.
- Probe baru diuji dalam container sementara dengan kode dan sertifikat read-only: primary terhubung sekitar 1,09 detik, secondary sekitar 0,29 detik. Durasi bergantung jaringan; ini bukan jaminan waktu respons tetap.
- Asset favicon `/brand/kemensos.png` merespons HTTP 200.

## Catatan yang masih perlu ditindaklanjuti

Laporan otomatis untuk `BBPPKS-BANDUNG-CS-BACKUP` pada 9 Oktober berstatus `PARTIAL`. Penyebab yang tercatat: trigger host-down tidak dapat dipilih otomatis. Laporan PDF berhasil dibuat, tetapi downtime tidak dapat dihitung. Worker tetap sehat dan melakukan polling, sementara status scheduler menjadi `error` karena `last_error` jadwal tersebut masih berisi peringatan.

Jadwal otomatis saat ini selalu memakai pemilihan trigger otomatis. Agar downtime pada jadwal itu tersedia, konfigurasi Zabbix perlu menyediakan tepat satu trigger host-down aktif yang cocok untuk host tersebut. Pada ekspor PDF manual, trigger dapat dipilih melalui kontrol downtime. Tidak ada trigger atau jadwal produksi yang diubah selama audit ini.

Log juga mencatat respons 502 sementara dari endpoint daftar host primary. Pengambilan host kedua server berhasil pada pemeriksaan terakhir. Penyebab gangguan terdahulu belum dapat dipastikan dari log yang ada; optimasi probe mengurangi beban pemeriksaan, tetapi tidak menjamin gangguan upstream tidak berulang.

Audit ini tidak menguji seluruh host/periode pada Zabbix, tidak menghasilkan laporan baru di produksi, dan tidak menerapkan ulang layanan. Backup sebelumnya tetap tersedia sebagai snapshot sebelum perbaikan audit. Container perlu dibuild dan diterapkan ulang untuk menggunakan perubahan aplikasi ini.

Pembaruan setelah audit: frontend telah dibuild dan diterapkan ulang untuk [tema dashboard berdasarkan referensi](dashboard-reference-theme.md). Perbaikan backend pada audit ini masih berada di kode lokal karena pembaruan tema hanya mengganti frontend.
